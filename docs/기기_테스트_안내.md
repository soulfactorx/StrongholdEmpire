# 기기에서 시험하기 (Android · 웹 · PC)

푸시할 때마다 GitHub Actions의 **내보내기** 워크플로(`.github/workflows/export.yml`)가
Android 디버그 APK, 웹, 윈도우, 리눅스 빌드를 만들어 아티팩트로 올린다.
리눅스 빌드로 자체 점검(`--self-check`)을 돌려 데이터·그림·소리가 패키지에 들어갔는지도 확인한다.

## 1. Android 폰에서 (APK 직접 설치)

1. GitHub 저장소 → **Actions** 탭 → 왼쪽에서 **내보내기** → 맨 위(가장 최근) 실행을 연다.
2. 아래 **Artifacts**에서 `android-apk`를 받는다. zip 안에 `StrongholdEmpire.apk`가 있다.
   - 폰의 브라우저로 GitHub에 로그인해 바로 받아도 되고, PC에서 받아 USB·메신저·드라이브로 폰에 옮겨도 된다.
3. 폰에서 zip을 풀고 `StrongholdEmpire.apk`를 누른다.
   - 처음이면 "출처를 알 수 없는 앱 설치" 허용을 묻는다. 파일을 연 앱(파일 관리자·Chrome 등)에 허용한다.
   - Play 프로텍트 경고가 나오면 "무시하고 설치"를 고른다. (디버그 키로 서명한 개인 시험용이라 나오는 경고)
4. 설치한 **강호제패**를 실행한다. 가로 화면, 전체 화면(몰입 모드)으로 뜬다.

알아 둘 점
- 64비트 ARM(arm64-v8a) 기기용이다. 최근 몇 년 사이의 폰은 대부분 해당된다.
- 디버그 키를 실행마다 새로 만들므로, **새 APK를 덮어 설치하면 "서명이 다르다"며 실패**할 수 있다.
  그때는 기존 앱을 지우고 설치한다. (세이브도 함께 지워진다. 세이브를 지키려면 고정 키를 저장소 Secret에 두는 방식으로 바꾼다)
- 홈 버튼으로 나가거나 전화가 오면 자동 저장 슬롯에 저장된다. 다시 열고 [불러오기] → 자동 저장.

### USB로 바로 실행 (PC에 Godot 편집기가 있을 때)

1. 폰: 설정 → 휴대전화 정보 → 빌드 번호 7번 눌러 개발자 옵션 켜기 → 개발자 옵션에서 **USB 디버깅** 켜기.
2. PC: Godot 4.7.1 편집기 + Android SDK(Android Studio로 설치)·JDK 17. 편집기 설정 → 내보내기 → Android에 SDK·JDK 경로 지정.
3. 편집기 → 내보내기 템플릿 관리에서 4.7.1 템플릿 설치.
4. 폰을 USB로 잇고 편집기 오른쪽 위 **원클릭 배포(Android 아이콘)** 를 누르면 설치·실행된다.
   이때는 편집기의 디버거·출력 창에 폰의 로그와 오류가 바로 보인다.

## 2. 폰·PC 브라우저에서 (웹)

### GitHub Pages (주소로 바로 열기)
`main`에 머지될 때마다 내보내기 워크플로가 웹 빌드를 GitHub Pages에 배포한다.
주소는 **https://soulfactorx.github.io/StrongholdEmpire/** 이다 (저장소 Settings → Pages에서도 확인).
- 처음 한 번: 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 바꾼다.
  바꾸기 전에 돌린 배포는 실패하므로, 바꾼 뒤 Actions → 내보내기 → 최근 main 실행에서 **Re-run all jobs**를 누른다.
- 비공개 저장소는 GitHub 유료 요금제에서만 Pages를 쓸 수 있다. Pages 사이트는 주소를 아는 누구나 열 수 있다.
- 웹 빌드는 설치형 앱(PWA)이라 서비스 워커가 파일을 보관한다. 새 버전이 배포되면 게임 안에 "새 버전이 있습니다" 창이 뜨고,
  [지금 업데이트]를 누르면 자동 저장 뒤 새 버전으로 다시 불러온다. 창이 안 뜨면 게임 탭(홈 화면 앱 포함)을 모두 닫았다가 다시 연다.
- GitHub Pages도 파일을 10분 정도 캐시하므로, 머지 직후에는 몇 분 기다린다. 배포 여부는 Actions → 내보내기 → 최근 main 실행의 deploy-pages 작업으로 확인한다.

### 직접 서버 띄우기

- 아티팩트 `web`을 받아 풀고, 그 폴더에서 웹 서버를 띄워 연다. 파일을 더블클릭해서는 열리지 않는다.
  ```
  cd web
  python3 -m http.server 8000
  ```
  PC 브라우저에서 `http://localhost:8000`, 같은 와이파이의 폰에서는 `http://<PC의 IP>:8000`.
- 단일 스레드 빌드라 특별한 서버 헤더 없이 GitHub Pages·itch.io 같은 정적 호스팅에 올려도 된다.
- 첫 화면에서 한 번 눌러야 소리가 난다. (브라우저 자동 재생 정책)
- 세이브는 브라우저 저장소에 남는다. 탭을 옮기면 자동 저장한다.

## 3. PC (윈도우 · 리눅스)

- 아티팩트 `windows`의 `StrongholdEmpire.exe` 하나로 실행된다(데이터 포함). 서명하지 않아 SmartScreen 경고가 나오면 "추가 정보 → 실행".
- 리눅스 빌드는 아티팩트로 올리지 않는다(자체 점검용). 필요하면 워크플로에 업로드 단계를 더한다.

## 4. 로컬에서 직접 내보내기

내보내기 템플릿(4.7.1)을 설치한 Godot으로:
```
godot --headless --path . --export-release "Web" build/web/index.html
godot --headless --path . --export-release "Linux" build/linux/StrongholdEmpire.x86_64
cd /tmp && /path/to/build/linux/StrongholdEmpire.x86_64 --headless -- --self-check   # 프로젝트 폴더 밖에서 실행
```
Android는 위 USB 절차의 SDK·JDK 설정이 있어야 한다: `--export-debug "Android" build/android/StrongholdEmpire.apk`

## 버전 올리기

`export_presets.cfg`의 Android `version/code`(정수, 올릴 때마다 +1)와 `version/name`을 함께 바꾼다.

# 강호제패 구현 계획 (완성도 향상)

**작성일**: 2026년 10월 17일 (갱신: 플랫폼·한 판 길이·아트 방향 결정, M4-1·M4-0·M4-3·M6-3·M6-5·M5-1·M4-2·M6-4·M7-2 완료)
**기준 브랜치**: `claude/game-completion-plan-ivm1qx`
**관련 문서**: `강호제패_전체_게임_디자인_문서.md`(기획), `기연_데이터_형식.md`, `NPC_문파_데이터_형식.md`

### 1.2 기술 부채

- `smoke_test.gd`가 1,200줄짜리 단일 파일이다. 영역별로 나눠야 유지보수가 쉽다.
- `combat_controller.gd`(650줄)에 입력·화면·행동 처리가 섞여 있다. 행동 처리는 `CombatRules`처럼 분리할 여지가 있다.
- `game_manager.gd`가 턴·전투·문파전·저장을 모두 맡는다. 세이브 직렬화 조립과 전투/전쟁 중계를 나눌 수 있다.
- `RelationshipData.get_combat_defense_modifier()`가 어디서도 쓰이지 않는다.
- `martial_art_screen.gd`가 프리셋 경로를 직접 들고 있다. `MartialArtLibrary`를 쓰도록 바꿔야 한다.
- 세이브 버전(현재 3)마다 흩어진 기본값으로 호환을 처리한다. 버전별 마이그레이션 함수로 모아야 한다.
- CI가 없다. 테스트는 수동으로만 돈다.

## 3. M4. 서사와 엔딩

### M4-0. 시나리오 시스템 (중~대) — 완료
한 판의 길이와 성격은 시나리오마다 다르다. 시나리오를 데이터로 추가하고,
파라미터로 게임 길이와 난이도를 조절할 수 있게 한다.

- 시나리오 정의: `data/scenarios/<id>/scenario.json`
  - 기본 정보: `id`, `title`, `description`, 시대 이름(예: "천하대란 원년"), 대표 이미지
  - 구성: 등장 세력 목록과 세력별 수치 덮어쓰기, 등장 인물 목록, 선택 가능한 시작 역할
  - 전용 콘텐츠: 같은 폴더의 `events/`, `endings/`, `npcs/`를 공용 데이터에 더해 읽는다
- 게임 길이·난이도 파라미터 (`parameters`, 모두 기본값이 있고 새 게임 화면의 "세부 설정"에서 바꿀 수 있음)

  | 파라미터 | 의미 | 예시 |
  |---|---|---|
  | `time_limit_years` | 제한 연수. 끝나면 시대 종결 엔딩(점수·평가) | 10 / 20 / 없음 |
  | `legacy_enabled`, `max_generations` | 세대 전승 허용과 최대 세대 | 켜짐, 3세대 |
  | `income_scale`, `upkeep_scale` | 수입·유지비 배율 | 1.0 / 0.8 |
  | `exp_scale` | 경험치 배율 (성장 속도) | 1.5면 짧은 판 |
  | `event_rate` | 계절마다 기연이 일어날 확률 | 0.6 ~ 1.0 |
  | `world_growth_scale` | 세력 성장·침공 속도 | 1.0 / 1.5 |
  | `enemy_strength_scale` | 전투·문파전 적 강도 | 0.8 / 1.0 / 1.2 |
  | `victory_endings` | 이 시나리오에서 승리로 치는 엔딩 목록 | 정파 통일, 신파 창설 |
  | `ironman` | Ironman 강제 여부 | 꺼짐 |

- 구현 방식
  - `GameBalance`는 기본값으로 남기고, 실행 중에는 `ScenarioRules`(현재 시나리오의 파라미터를 반영한 값)를 통해 읽는다
  - 시나리오 id와 파라미터를 세이브에 저장한다
  - 기연 조건에 `scenario`(시나리오 id), `years_left`(남은 연수) 추가
- 첫 시나리오 3종 (같은 세계, 다른 길이)
  - 「천하대란」: 표준 20년, 현재 내용 그대로
  - 「흑풍의 겨울」: 5년 단기전. 흑풍채 침공을 막아 내는 방어 중심
  - 「강호백년」: 제한 없음, 세대 전승 5세대, 천마신교 대침공이 후반에 발생
- 대상: 새 `scripts/Systems/scenario_manager.gd`, `scenario_rules.gd`, `new_game_screen`, `game_manager.gd`
- 완료 기준: 시나리오 선택과 파라미터가 수입·경험치·기연 확률·제한 연수에 반영되는지 테스트, 시나리오별 전용 기연 로드 테스트
- 결과: 계획한 파라미터에 `end_on_victory`(승리 엔딩 시 즉시 완수)를 더해 10종. `ironman`은 M8-4에서 저장 기능과 함께 넣는다.
  시나리오 전용 엔딩은 처음에 `scenario.json`의 `endings`로 두었다가 M4-3에서 `endings/` 폴더로 옮겼다.
  시대 종결·시나리오 완수 시 점수·등급 평가. 형식은 `docs/시나리오_데이터_형식.md`

### M4-1. 기연 문법 확장 (소) — 완료
스토리 체인을 데이터로 쓰려면 기연 조건이 몇 가지 더 필요하다.

- 할 일
  - 조건 `year`(연차 비교), `turns_since_flag`(플래그가 켜진 뒤 N계절 경과), `relationship_type`(관계 유형 일치), `role_history`(거쳐 온 역할) 추가
  - 효과 `set_bond_type`(관계 유형 변경), `add_relationship`(새 인물과 관계 생성), `learn_art`(무공 습득), `end_game`(지정 엔딩으로 종료) 추가
  - 기연 가중치 `weight` 추가: 스토리 핵심 기연이 무작위 풀에 묻히지 않게
  - 플래그를 켠 계절을 기록: `story_flags`에 값과 함께 턴 인덱스 저장
- 대상: `event_manager.gd`, `docs/기연_데이터_형식.md`, `smoke_test.gd`
- 완료 기준: 새 조건·효과마다 검증 오류 검출 테스트와 적용 테스트가 있다
- 결과: 조건 4종·효과 4종·가중치 추가. 플래그 시점은 `GameManager.flag_turns`, 역할 기록은 `role_history`로
  관리하고 세이브 버전 4로 저장한다. 새 문법을 쓰는 기연 2종(「남궁휘와의 결의」, 「스승의 비전」) 추가,
  「혈영의 밀서」에 관계 생성 효과 연결

### M4-2. 스토리 아크 5개 (대) — 완료
디자인 문서 6.3절의 아크를 3~6단계 연쇄 기연으로 만든다.

| 아크 | 흐름(예시) | 연결 시스템 |
|---|---|---|
| 복수와 용서 | 스승 피습 → 범인 추적(전투) → 처단 또는 용서 | 관계(원한), 전투, 도덕 |
| 승계와 배신 | 문주 후계 다툼 → 중간관리자 음모 → 내분 전투 | 역할 전환, 문파전 |
| 금단의 사랑 | 남궁세가 인물과 인연 → 가문 반대 → 도주·혼인·비극 | 관계(연애), 세력 태도 |
| 스파이 이중생활 | 기존 스파이 기연 확장 → 노출 위기 3회 → 이중첩자 선택 | 스파이 노출도(M5-1) |
| 마교 대침공 | 혈영의 밀서 → 정파 연합 회의 → 천마신교 침공 방어전 | 세력 AI(M6-2), 대규모 전투 |

- 아크당 기연 4~8개, 전투 1~2회, 갈림길 엔딩 1개 이상
- 대상: `data/events/arcs/` (하위 폴더로 묶음, 로더가 하위 폴더도 읽도록 수정)
- 완료 기준: 아크마다 처음부터 끝까지 자동으로 진행하는 테스트(선택지를 고정해 플래그와 결과 확인)
- 결과: 아크 5개, 기연 38개(아크당 6~8개), 데이터 전투 13개, 아크 엔딩 8개(`auto: false`), 새 인물 6명.
  - 전투를 데이터로 정의하는 `CombatLibrary`(`data/combats/`, `docs/전투_데이터_형식.md`)를 추가했다.
    인물 아군(`allies`), 문파 제자 합류, 능력치 보정, 패배 플래그(`defeat_flag`)로 갈림길을 만든다
  - 기연 로더가 하위 폴더를 읽는다. 후보 목록을 돌려주는 `EventManager.get_candidates` 추가
  - 「혈영의 밀서」를 거절하면 `cheonma_letter_refused`가 켜져 마교 대침공 아크로 이어진다(천하대란 전용.
    강호백년은 기존 시나리오 침공 기연을 쓴다)
  - 「승계와 배신」에서 후계자로 지명되면 중간관리자 승진·문주 승계 조건이 완화된다
  - 테스트: 아크마다 갈림길별 경로 2~3개를 선택지·전투 결과를 고정해 끝까지 진행한다

### M4-3. 엔딩 재설계 (중) — 완료
- 엔딩을 8~12개로 늘린다. 세력 굴복·태도, 아크 결말 플래그, 역할, 도덕, 명성을 조합한다.
  - 예: 정파 통일 = 문주 + 명성 100 + 흑풍채·천마신교 굴복
  - 예: 마교의 그림자 = 천마신교와 밀약(`cheonma_pact`) + 도덕 30 이하
  - 예: 은거 고수 = 낭인 + 레벨 15 + 무공 4개 이상 + 문파 관계 정리
- 엔딩 정의를 `data/endings/*.json`으로 옮긴다. 조건 문법은 기연 조건을 그대로 쓴다.
- 엔딩 화면에 그 판의 요약을 보여 준다: 연도, 역할 변천, 굴복시킨 세력, 창조한 무공, 주요 인연
- 대상: `ending_manager.gd`, `ending_screen.gd`, 새 `data/endings/`
- 완료 기준: 모든 엔딩에 도달하는 상태를 만들어 판정하는 테스트, 우선순위가 겹치는 엔딩이 없는지 검사하는 테스트
- 결과: 공용 엔딩 12종(데이터), 시나리오 전용 엔딩은 각 시나리오의 `endings/` 폴더로 이동.
  생을 마치는 `final` 엔딩(처형·피로 물든 길·은거 고수)은 전승 가능하면 즉시 후계자로, 아니면 이야기의 끝.
  조건 `subjugated_count`, `generation` 추가. 엔딩 화면에 판 요약·평가·분위기 색. 형식은 `docs/엔딩_데이터_형식.md`

### M4-4. 기연 콘텐츠 확장 (대, 계속)
- 목표: 기연 11개 → 80개 이상
  - 역할별 전용 10개 이상 × 7역할
  - 세력별 5개 이상 × 3세력
  - 계절·연차 이벤트 10개 (명절, 무림대회, 기근 등)
- 기연 작성 가이드를 `docs/기연_데이터_형식.md`에 덧붙인다: 문체, 선택지 수(2~4), 보상 크기 기준표
- 완료 기준: 무작위 상태 1,000개에서 계절마다 발생 후보가 1개 이상인 비율이 80% 이상 (테스트로 측정)

## 4. M5. 역할·관계 심화

### M5-1. 역할별 고유 행동 (대) — 완료
경영 화면의 행동 버튼을 역할에 따라 바꾼다. 공통 행동은 유지한다.

| 역할 | 고유 행동 | 고유 자원·위험 |
|---|---|---|
| 문주 | 문파 회의 소집, 사절 파견(M6-1) | 내부 불만도: 높으면 반란 기연 |
| 중간관리자 | 부서 지정(재정·수련·정보), 문주에게 건의 | 문주 신임도 |
| 막내 제자 | 스승에게 가르침 청하기, 외출(무작위 기연) | 행동 제한(시설 확장 불가) |
| 낭인 | 의뢰 게시판(전투·호위·수색), 이동(세력 변경) | 문파 지원 없음 대신 의뢰 보상 |
| 스파이 | 정보 수집(적 세력 정보 공개), 사보타주 | **노출도 게이지**: 100이면 처형 엔딩 |
| 암살자 | 표적 의뢰 수락 → 잠입 전투 | 현상금: 높으면 추격 전투 |
| 의뢰인(MERCENARY) | 계약 수주(세력별 임무), 계약 위반 | 세력별 신용도 |

- 의뢰인 역할을 실제로 구현한다: 시작 역할 또는 낭인에서 전환하는 경로를 만든다
- 역할 전환 경로를 넓힌다: 강등(실패 누적), 이적(다른 세력으로), 배신(문파를 떠나 적 세력으로)
- 대상: `role_manager.gd`, `management_screen.gd`(역할별 버튼 영역), 새 `scripts/Systems/role_actions.gd`
- 완료 기준: 역할마다 고유 행동이 1개 이상 동작하고 테스트가 있다
- 결과: `RoleActions`에 7역할 15개 행동. 역할 행동은 계절마다 한 번(역할 행동끼리 공유).
  역할 자원은 `GameManager.role_state` 하나에 담아 저장한다(세이브 8판).
  기연 조건·효과 `role_state`를 추가해 반란(불만도 70)·의심(노출도 60)·추격(현상금 50) 기연을 데이터로 만들었다.
  새 전투 3종(토벌·잠입·추격), 시작 역할 의뢰인 추가.
  전환: 낭인↔의뢰인, 이적(신용 40 → 그 세력 객경), 배신(스파이 → 잠입 세력, 도덕 30 이하 → 적대 세력),
  강등(중간관리자 실책 3회·신임 0), 축출(문주 불만도 100 → 낭인). 문주 승계에 신임도 50 필요.
  이적·배신하면 그 세력이 내 문파가 되고 옛 문파는 강호 세력이 된다.
  사절 파견은 기본 형태만 넣었다(태도 상승). 동맹·혼담 등은 M6-1에서 확장한다

### M5-2. 관계 진화 (중)
- 유대 단계가 바뀔 때 해당 인물의 전용 기연을 발생시킨다 (예: 남궁휘 유대 60 → 「라이벌의 고백」)
- 관계 유형 전환: 라이벌 → 혈맹, 사제 → 원한(배신), 낯선 사이 → 연애
- 인물과의 상호작용 행동: 대화, 선물, 비무 신청 (계절당 행동 횟수 제한)
- 관계 효과를 전투에 반영한다: 지금 쓰이지 않는 `get_combat_defense_modifier()`를 피해 계산에 연결하고, 혈맹이나 사제 관계의 인물이 아군으로 합류하게 한다
- NPC를 늘린다: 연애 상대 후보 2명, 각 세력의 2인자 1명씩, 낭인 동료 2명
- 대상: `relationship_manager.gd`, `relationship_data.gd`, `data/npcs/`, `combat_rules.gd`
- 완료 기준: 단계 변화 기연 트리거, 유형 전환, 아군 합류를 테스트로 확인

## 5. M6. 경영·외교·문파전

### M6-1. 외교 (중)
- 행동: 사절 파견(태도 +, 금화 소모), 동맹 제안(태도 50 이상), 혼담(연애 아크와 연결), 도전장(문파전 대상 지정 + 명성), 공물 요구(굴복한 세력에게서 계절 수입)
- 동맹 세력은 문파전에 원군 전력을 보탠다
- 대상: 새 `scripts/Systems/diplomacy_manager.gd`, 강호 정세 화면에 행동 버튼 추가
- 완료 기준: 행동별 비용·효과·조건 테스트

### M6-2. 세력 AI (중)
- 계절마다 각 세력이 행동을 고른다: 성장, 다른 세력 공격, 플레이어 침공, 외교
- 성향(정파·사파·마교)과 태도로 확률을 정한다. 수치는 `GameBalance`에 둔다
- 플레이어 침공은 방어전으로 이어진다: 문파전 화면을 방어 모드로 재사용하거나 전술 전투로 처리
- 세력끼리의 전쟁 결과를 강호 정세 화면의 "강호 소식"으로 보여 준다
- 완료 기준: 시뮬레이션 100판에서 세력 하나가 5년 안에 다른 세력을 모두 흡수하지 않는다(밸런스 테스트)

### M6-3. 문파전 개선 (중) — 완료
- 적 명령: 고정 순서 대신 성향별 선호와 확률로 고른다. 정찰(금화·정보)로 다음 명령을 엿볼 수 있게 한다
- 진형 선택(학익진·어린진·방원진): 명령 상성에 배율을 더한다
- 장수 개입: 이름 있는 제자나 동맹 인물을 라운드에 배치해 능력치를 보탠다
- 라운드별 결과를 보여 주는 연출 화면
- 문파전 보상·손실 수치를 `GameBalance`로 옮긴다
- 완료 기준: 같은 명령 조합으로 이기는 확률이 60% 이하가 되도록 밸런스 테스트
- 결과
  - 상성을 돌격 > 측면 > 방어 > 돌격으로 정리하고 후퇴는 손실 감소로 바꿈
  - 적은 성향별 가중치로 작전을 세우고(문파 데이터로 덮어쓰기 가능), 지난 전투의 아군 명령을 40% 확률로 맞받아침
  - 진형 3종(강화 1·약점 1), 장수(유대 50 이상 사제·혈맹 인물, 특기 명령), 정찰(점점 비싸짐, 스파이 절반)
  - 같은 명령 연속 사용 감점(×0.85), 전장의 변수(±10%)
  - 밸런스 테스트: 같은 전력에서 첫 대결 최선의 고정 조합 승률 56~60%, 같은 조합을 되풀이하면 29~34%
  - 이름 있는 제자를 장수로 세우는 것은 M6-4(제자 명단)에서 이어 간다

### M6-4. 제자 명단 (중) — 완료
- 제자 수 대신 이름과 능력치를 가진 개별 제자 목록(최대 30명)을 관리한다
- 훈련, 배치(서고·무술장·금고 담당 시 효율 보너스), 전투 참전 선택
- 방어전 아군은 명단에서 고르고, 전사한 제자는 명단에서 빠진다
- 세이브 버전을 올리고, 구버전의 제자 수는 무작위 제자로 채운다
- 완료 기준: 명단·배치·전사 반영, 구버전 세이브 변환 테스트
- 결과: `DiscipleData`(이름·경지·무력·신법·지혜·배치·출전·참전 횟수)와 `DiscipleRoster`.
  - 플레이어 문파만 명단을 쓴다(`SectData.use_roster`). `disciple_count`에 setter를 두어 값이 바뀌면 명단을 맞추므로
    기연·유지비·문파전 등 제자 수만 바꾸는 기존 코드가 그대로 동작한다. 줄어들 때는 맡은 일 없는 약한 제자부터 떠난다
  - 배치: 시설 레벨만큼 자리. 서고(지혜 → 연구점), 금고(지혜 → 금화), 무술장(계절 경험치). 예상 수지에 반영
  - 개별 수련(금화 20, 계절마다 한 번), 경지(최대 10)마다 능력치 +1, 문파전 전력에 경지 반영
  - 방어전 아군은 출전 지정 제자 → 강한 제자 순. 쓰러진 제자는 id로 명단에서 빠지고, 살아남은 제자는 경험을 얻는다
  - 경영 화면 [제자 명단] 팝업(48px 버튼, 스크롤). 세이브 9판, 구버전은 제자 수만큼 무작위 제자로 채운다
  - 이적·배신으로 옮겨 간 세력은 명단을 새로 만들고, 떠나온 문파는 제자 수만 남긴다

### M6-5. 경제 밸런스 (소) — 완료
- 문제: 아무것도 하지 않아도 자원이 계속 쌓인다(40계절에 금화 1,300 이상)
- 할 일: 시설 단계별 유지비 상향, 고급 시설(약방·연공실), 영약 구매, 행사 비용 등 금화를 쓸 곳을 만든다
- 완료 기준: 무행동 시뮬레이션의 10년 차 금화가 시작값의 2배 이하
- 결과
  - 해마다 재고 손실: 금화 500 초과분의 15%, 식량 300 초과분의 20%. 쌓아 두면 손해라 지출을 유도
  - 기본 금화 수입 20 → 15, 시설 유지비 단계당 3 → 4, 계절마다 저절로 오르던 명성 +1 대신 해마다 제자 5명당 +1
  - 쓸 곳: 약방(계절 내공 회복)·연공실(계절 수련 경험치), 확장할수록 오르는 시설 비용, 영약(최대 내공), 연회(명성)
  - 수입 계산을 `SectManager.compute_seasonal_income`으로 옮기고 수치는 모두 `GameBalance`로. 경영 화면에 다음 계절 예상 수지
  - 시뮬레이터(`scripts/Tools/economy_sim.gd`, 10년): 무행동 금화 약 1,320 → 800~870,
    제자 18명 운영 640~700, 시설·영약·연회에 적극 투자하면 금화를 거의 다 쓰고 명성 80~98, 무리한 훈련은 여전히 기근

## 6. M7. 무공 심화

### M7-1. 연구 리스크와 숙련 (소)
- 실패 결과를 다양화한다: 반동(현재), 주화입마(능력치 일시 하락), 천벌 기연
- 숙련도: 사용 횟수에 따라 위력과 내공 효율이 오른다(3단계)
- 음양을 전투에 반영한다: 양은 피해 증가·내공 소모 증가, 음은 피해 감소·상태 효과 확률 증가, 균형은 보정 없음

### M7-2. 전수와 비전 (중) — 완료
- 습득한 무공을 제자에게 전수한다. 제자 명단(M6-4)과 연결되며, 전수한 제자가 방어전에서 그 무공을 쓴다
- 문파 비전: 문파 공동 연구로 강화한 무공을 비전으로 지정해 세대 전승 때 물려준다
- 상대 무공 분석: 전투에서 본 적의 무공을 연구해 상극 속성 카운터 무공의 성공률을 높인다
- `martial_art_screen.gd`가 `MartialArtLibrary`를 쓰도록 정리한다
- 결과
  - 전수: 제자 명단의 [무공 전수]. 연구점 10 + 복잡도 × 5, 제자 레벨은 복잡도 ÷ 2(올림) 이상. 제자는 무공 하나(복제본)를 익혀 방어전에서 쓴다
  - 강화: 무공 연구소의 [무공 강화]. 연구점 30 + 단계 × 20으로 3단계까지, 단계마다 피해 +3(회복 +4)·내공 소모 −1. 반드시 성공
  - 비전: 1단계 이상 강화한 무공을 문파 비전으로 지정(`SectData.secret_art`). 세대 전승 때 후계자가 익히고, 전수 비용이 절반
  - 분석: 전투에서 본 적 무공을 기록(`GameManager.observed_arts`)하고, 연구점 25로 그 속성을 분석하면
    상극 속성 무공 창조 성공률 +15%. 혈영에게 뇌전장(화)을 배정해 분석 대상을 만들었다
  - 비급 목록은 `MartialArtLibrary.get_all()`을 쓴다. 비급을 익힐 때 복제본을 써서 강화가 원본에 번지지 않게 했다
  - 세이브 10판: 강화 단계, 제자 무공, 문파 비전, 본 무공·분석 속성

### M7-3. 무공 콘텐츠 (소)
- 프리셋 무공 2개 → 15개 이상: 세력별 대표 무공, 카테고리별 하나씩
- 세력 문주와 2인자에게 무공을 배정한다

## 7. M8. 표현과 편의

### M8-1. 아트 (대, 외주 또는 생성 도구 활용) — 방향 확정: 수묵담채 + 장기말 토큰

  - 인물 초상화: NPC 8명 + 주인공 시작 역할 3종 + 제자 공용
  - 전투 타일셋: 평지·수풀·물·고지·벽
  - 유닛 스프라이트: 아군·적 기본형 4~6종
  - UI 테마: 테두리, 버튼, 패널 (산수화·먹 질감)
- 데이터 연결: NPC JSON에 `portrait`, 세력 JSON에 `emblem` 필드 추가
- 전투 렌더링을 `ColorRect` 대신 `TileMapLayer`와 `Sprite2D`로 바꾼다

### M8-2. 사운드 (중)
- BGM 4곡: 메인, 경영, 전투, 엔딩
- 효과음: 클릭, 성공·실패, 타격, 무공 시전, 레벨업, 기연 발생
- `AudioManager`를 실제 스트림 재생과 음량 버스(BGM·효과음)로 바꾼다

### M8-3. UI/UX (중)
모바일을 최우선으로 설계한다. 마우스 호버에 기대는 상호작용을 만들지 않는다.

- 입력
  - 터치: 탭으로 선택·실행, 길게 눌러 툴팁, 두 손가락으로 전투 지도 확대·이동
  - 게임패드(Switch·PS·Xbox): 모든 버튼에 포커스 이동 경로를 지정하고, 전투 격자에 커서를 둔다
  - 키보드·마우스(PC·Mac): 단축키, 호버 툴팁은 길게 누르기와 같은 내용을 보여 준다
- 화면
  - 터치 목표 최소 48px(기준 해상도 720p), 본문 글자 최소 16px
  - 휴대폰 노치·홈 바를 피하는 안전 영역 여백
  - 화면 비율 19.5:9~4:3 대응 (`stretch/aspect = expand`)
  - 가로 화면 기준. 세로 화면 지원은 출시 후 검토
- 툴팁: 능력치·지형·무공 효과·유지비 계산 근거
- 첫 판 튜토리얼: 경영 → 기연 → 비무 → 무공 창조 순서로 안내하는 단계형 기연
- 확인 대화상자: 메인 메뉴로 나가기, 새 게임, 후퇴
- 옵션 화면: 음량, 해상도·전체화면, 전투 속도, 텍스트 크기
- 전투: 행동 실행 취소(이동 한정), 적 차례 연출 속도, 키보드 단축키
- 연간 보고서: 해가 바뀔 때 1년 요약 팝업

### M8-4. 저장 (소)
- 다중 슬롯(3개)과 슬롯별 요약(연도·인물·역할)
- 계절 진행 시 자동 저장
- Ironman 모드: 새 게임에서 선택, 자동 저장만 허용, 불러오기 1회
- 세이브 마이그레이션: `SaveManager.migrate(data)`가 버전 1→2→3→…을 순서대로 변환

## 8. M9. 품질과 출시

### M9-1. 테스트 구조 (소)
- `smoke_test.gd`를 영역별 파일로 나눈다: `test_combat.gd`, `test_events.gd`, `test_world.gd` 등. 하나의 진입 스크립트가 모두 실행한다
- 밸런스 시뮬레이터를 정식 도구로 둔다: `scripts/Tools/balance_sim.gd` (전투 자동 플레이, 장기 경제, 세력 AI)

### M9-2. CI (소)
- GitHub Actions에서 Godot 헤드리스로 클래스 캐시 갱신과 스모크 테스트를 돌린다
- 기연·NPC·문파 JSON 검증도 같은 단계에서 실패로 잡는다

### M9-3. 내보내기 (중)
- 출시 우선순위: **모바일(Android → iOS) → 웹 → Windows → Mac → Switch → PlayStation → Xbox**
- 내보내기 프리셋을 우선순위대로 만든다. 모든 프리셋의 비리소스 파일 필터에 `*.json`을 포함한다
- 모바일: 저장 위치(`user://`), 앱 일시정지·복귀 시 자동 저장, 저사양 기기 성능 측정
- 웹: 첫 로딩 용량 관리(폰트 서브셋, 텍스처 압축), 브라우저 저장소에 세이브
- 콘솔: Godot 공식 빌드에 콘솔 내보내기가 없으므로 콘솔 이식 전문 업체나 퍼블리셔와 협력한다.
  플랫폼별 인증 요건(저장 처리, 패드 조작, 화면 안전 영역)은 M8-3 단계에서 미리 맞춰 둔다
- 내보낸 빌드에서 데이터 폴더 읽기(`.remap` 처리 포함)를 확인하는 테스트를 실행한다

### M9-4. 현지화 준비 (중, 선택)
- 게임 내 문구를 `tr()` 키로 옮기고 한국어 번역 파일을 기본으로 둔다
- 데이터 JSON의 문구는 키 또는 언어별 필드로 확장할 수 있게 설계만 해 둔다

### M9-5. 밸런스 패스 (중)
- 목표 지표
  - 첫 판 평균 플레이 시간: 2~3시간
  - 엔딩 분포: 어떤 엔딩도 도달률 40%를 넘지 않음 (시뮬레이션 기준)
  - 전투: 같은 레벨의 정공법으로 승률 70~85%, 끝났을 때 남은 체력 30~60%
  - 게임오버: 무리한 확장 전략일 때만 발생
- 전투 자동 플레이 시뮬레이션에서 현재 남은 체력은 35~75%다. 적 AI와 피해 배율을 함께 조정한다

## 10. 작업 원칙

- **데이터 우선**: 기연·인물·세력·엔딩·무공은 JSON 또는 `.tres`로 정의한다. 코드에는 해석기만 둔다
- **수치는 `GameBalance`에**: 밸런스 값을 코드 곳곳에 흩지 않는다
- **화면 전환은 `SceneRouter`로**
- **테스트와 함께**: 기능마다 스모크 테스트를 추가한다. 커밋 전에 전체 테스트를 실행하고 결과를 확인한다
- **세이브 호환**: 저장 형식을 바꿀 때는 버전을 올리고 구버전 변환 테스트를 추가한다
- **시뮬레이션으로 밸런스 확인**: 전투·경제 수치를 바꾸면 자동 플레이 결과를 함께 기록한다
- **모바일 우선**: 새 화면은 터치로 모든 기능을 쓸 수 있어야 한다. 호버 전용 정보나 작은 버튼을 만들지 않는다
- **한국어**: 코멘트·커밋·PR·문서는 한국어로 쓴다 (`CLAUDE.md`)

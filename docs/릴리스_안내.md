# 릴리스 내기

`v`로 시작하는 태그를 올리면 **내보내기** 워크플로(`.github/workflows/export.yml`)가 그 버전으로 네 플랫폼을 내보내고
GitHub 릴리스를 만들어 파일을 붙인다.

| 파일 | 내용 |
|---|---|
| `StrongholdEmpire-<버전>-android.apk` | Android (arm64-v8a) |
| `StrongholdEmpire-<버전>-web.zip` | 웹 빌드 (웹 서버에 그대로 올림) |
| `StrongholdEmpire-<버전>-windows.zip` | Windows 64비트 실행 파일 (아이콘·버전 정보 포함) |
| `StrongholdEmpire-<버전>-linux.zip` | Linux x86_64 실행 파일 |
| `SHA256SUMS.txt` | 파일 검증용 해시 |

## 1. 릴리스 내는 법

`main`에 머지된 상태에서:

```sh
git checkout main && git pull
git tag v1.0.0
git push origin v1.0.0
```

또는 GitHub 웹에서 **Releases → Draft a new release → Choose a tag**에 새 태그(`v1.0.0`)를 적고 **Publish release**.
이때는 적어 둔 릴리스에 파일만 붙는다.

- 버전은 태그에서 정한다. `v1.2.3` → 게임 버전 `1.2.3`(첫 화면 아래에 보임), Android 버전 코드 `10203`, Windows 파일 버전 `1.2.3.0`.
  저장소의 `project.godot`(`config/version`)은 바꾸지 않아도 된다. 태그가 없는 평소 빌드는 `project.godot`의 버전을 쓴다.
- `v1.0.0-beta.1`처럼 `-`가 붙은 태그는 **시험판(Pre-release)** 으로 낸다.
- 릴리스 노트에는 설치 안내 표와 지난 릴리스 이후의 PR 목록(자동 생성)이 들어간다.
- 진행은 Actions → 내보내기에서 본다. 스모크 테스트도 같은 태그로 함께 돈다.

## 2. Android 릴리스 키 (선택, 한 번만)

비밀값이 없으면 APK를 실행마다 새로 만드는 디버그 키로 서명한다. 그러면 새 버전을 덮어 설치할 수 없어 앞 버전을 지워야 한다.
고정 키를 한 번 만들어 저장소 비밀값에 넣으면 릴리스 APK는 그 키로 서명되어 덮어 설치된다. (Play 스토어에 올릴 때도 이 키가 필요하다)

```sh
keytool -genkeypair -v -keystore release.keystore -alias gangho -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 release.keystore > release.keystore.b64     # macOS는 base64 -i release.keystore
```

저장소 **Settings → Secrets and variables → Actions → New repository secret**:

| 이름 | 값 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `release.keystore.b64` 파일 내용 |
| `ANDROID_KEYSTORE_USER` | 별칭 (위 예에서는 `gangho`) |
| `ANDROID_KEYSTORE_PASSWORD` | 키 저장소 비밀번호 |

`release.keystore`와 비밀번호는 저장소에 올리지 말고 따로 안전하게 보관한다. 잃어버리면 같은 앱으로 업데이트할 수 없다.

## 3. 알아 둘 점

- Windows 실행 파일은 코드 서명을 하지 않아 처음 실행할 때 SmartScreen 경고가 나온다 ("추가 정보 → 실행").
- 웹은 릴리스와 별개로 `main`에 머지될 때마다 GitHub Pages(https://soulfactorx.github.io/StrongholdEmpire/)에 배포된다.
- 같은 태그를 다시 쓰려면 릴리스와 태그를 모두 지운 뒤 다시 올린다 (`git push --delete origin v1.0.0`).
